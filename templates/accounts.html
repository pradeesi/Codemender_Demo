How CodeMender Solves This

The Vulnerability: In app.py: accounts_view(), user input search_term is directly concatenated into the SQL statement via Python f-string: 

query = f"SELECT ... WHERE is_confidential = 0 AND customer_name LIKE '%{search_term}%'"

CodeMender Workflow: cm find statically identifies the taint-flow from request.args.get() into cursor.execute(). cm verify executes a harmless verification query confirming exploitability. cm fix rewrites the SQL execution to use SQLite parameterized query bindings: cursor.execute("... LIKE ?", (f"%{search_term}%",)), runs the test suite to verify no regressions, and applies the validated patch.
